## Legacy receipt conflict

The first hardening push applied through `20260820170902` and stopped transactionally in
`20260820171706_booking_commit_leases`: two historical booking intents each had five
`unknown` receipts. There were zero accepted or failed receipts in either group. The failed
migration left no slot-lease table, overlap constraint, or unique receipt index.

The forward-only reconciliation is
`supabase/migrations/20260821234000_legacy_unknown_receipt_reconciliation.sql`. It:

1. takes an access-exclusive receipts lock;
2. preserves the earliest unknown receipt as the canonical intent evidence;
3. records every later receipt and its original intent in an append-only quarantine;
4. clears only the duplicate intent link, never deleting a receipt;
5. fails if any booking-intent duplicate remains;
6. is idempotent when the ordered migration runner reaches it later.

Because its CLI-generated timestamp sorts after the historical migration that needs clean
input, execute the exact reviewed file once without inserting migration history, then resume
the normal ordered push. Do not copy the SQL into an ad-hoc editor.

```bash
cd /Users/d1f/.codex/worktrees/ligou-v0.2-browser-pilot/Ligou.AI

bunx supabase db query --linked \
  --file supabase/migrations/20260821234000_legacy_unknown_receipt_reconciliation.sql

bunx supabase db query --linked --output-format json \
  "select
     (select count(*) from public.legacy_unknown_receipt_quarantine) as quarantined,
     (select count(*) from public.receipts r
        join public.legacy_unknown_receipt_quarantine q on q.receipt_id=r.id
        where r.intent_id is null) as quarantined_unlinked,
     (select count(*) from public.receipts r
        where r.outcome='unknown' and r.intent_id in
          (select distinct q.original_intent_id from public.legacy_unknown_receipt_quarantine q)) as canonical_unknowns,
     (select count(*) from public.receipts r
        where r.id in (select q.receipt_id from public.legacy_unknown_receipt_quarantine q)
           or r.intent_id in (select distinct q.original_intent_id from public.legacy_unknown_receipt_quarantine q)) as preserved_receipts,
     (select count(*) from (
        select intent_id from public.receipts
        where kind='booking' and intent_id is not null
        group by intent_id having count(*) > 1
      ) duplicates) as remaining_duplicates,
     (select count(*) from pg_trigger
        where tgname in ('receipts_append_only','legacy_unknown_receipt_quarantine_append_only')
          and tgenabled='O') as append_only_triggers_enabled;"

bunx supabase db push --linked --password "$SUPABASE_DB_PASSWORD" --skip-vault --yes
```

The shell running those commands must already hold `SUPABASE_ACCESS_TOKEN` and
`SUPABASE_DB_PASSWORD`, loaded without echo from the mode-`0600` files in
`~/.config/ligou/`. Never paste either value into this runbook or command output.

Required observed values before continuing: `quarantined = 8`,
`quarantined_unlinked = 8`, `canonical_unknowns = 2`, `preserved_receipts = 10`,
