# Website V2 sales RPC contract

All RPCs are `public`, `SECURITY INVOKER`, EXECUTE service_role only, return JSONB. Every timestamp is UTC. Money is numeric USD, never inferred from duration. Configuration singleton defaults disabled with owner_user_id NULL, max_minutes=5, session_cost_ceiling_usd=1.50, daily_budget_usd=15, visitor_daily_limit=3, network_daily_limit=10. Configured limits may only tighten these maxima. Runtime heartbeat TTL 30 seconds. `sales_configuration` is server-only. Existing tenant tables remain untouched.

## Public Edge persistence
- `sales_admit(p_request_id uuid, p_token_hash text, p_visitor_hash text, p_network_hash text, p_offer_sdp text) -> {session_id,status,max_minutes,expires_at}`. Hash inputs are 64 lowercase hex. Atomic singleton configuration lock serializes admission, global active slot, UTC day budget holds, visitor and network counters. session_id equals request_id. Same request+token replays; mismatched token throws `session_not_found`. Daily budget counts greatest(reserved,observed) for unsettled sessions (including earlier-day unresolved sessions), settled actual usage for current-day sessions. Unknown provider creation/usage does not free holds.
- `sales_public_session(p_session_id uuid,p_token_hash text,p_network_hash text,p_end boolean default false) -> public state`. `p_end=true` durably sets stop_requested; if the session does not yet exist, records a token-bound cancellation tombstone so a delayed start returns ended without spending or admission. New tombstones require a validated network hash and are atomically bounded at10/network/UTCday and100globally/UTCday; exhausted bound throws cancellation_limit(429). Existing admitted ends and matching cancellation/status replays bypass this quota and do not take the global configuration lock; unclaimed pending can safely end with zero usage. Public state has only session_id,status,max_minutes,expires_at,sdp (only ready),error,provider_termination_state. Capability valid until expires_at+1 hour for polling/end; offer expires at five minutes.

- `sales_client_connected(p_session_id uuid,p_token_hash text) -> public state`. Edge action connected uses the same visitor capability and trusted proxy. Persists client_connected_at once, only when ready and unexpired; pending/starting reject session_not_ready(409). Ending/terminal/expired acknowledgement returns current state without activating or recording a new connection. Acknowledgement timestamp is returned only in WorkerSession.

## Worker
- `sales_heartbeat(p_worker_id text) -> {enabled,server_time}`. Called only by enabled sidecar; disabled config never permits admission regardless of heartbeat.
- `sales_claim(p_worker_id text) -> null | WorkerSession`. Lease duration 30s. Claims pending, and recovers expired leases for known providers/expired sessions for termination. Expired ambiguous create without provider ID becomes quarantined and retains budget/global slot; never reissued. Call periodically even if admission disabled to drain old sessions.
- `sales_worker_apply(p_session_id uuid,p_claim_token uuid,p_operation text,p_payload jsonb default '{}') -> WorkerSession`. Every call locks row and checks current claim_token and unexpired lease. The following operations are supported:
  - `renew`: extend lease 30 seconds; may continue after configuration disabled to terminate.
  - `create_intent`: `{model:string}`. Only starting with no previous unresolved intent/provider; returns persisted intent BEFORE external create. Repeated intent is rejected. Allowed model names are validated by runtime against deployed provider config, persisted verbatim (max 120 chars).
  - `provider_rejected`: `{error?:string}`. Explicit provider non-acceptance only: clears intent to permit one runtime-controlled fallback; DB limits total create attempts to two. Never use for timeout/network ambiguity.
  - `provider_ready`: `{provider_call_id:string,answer_sdp:string,model:string,ready?:false}`. Requires outstanding intent. Saves ID and SDP atomically but remains starting, with SDP hidden until activate. If stopped/expired returns ending instead of ready. Never expose provider ID to visitor.
  - `activate`: `{}`. Only after runtime sideband session.update acknowledgement. Moves starting to ready, or ending if stopped/expired/disabled.
  - `quarantine`: `{error:string,provider_call_id?:string}`. Optional known provider ID is durably preserved. Ambiguous outcome; keeps hold/global slot. If provider ID known worker must attempt termination; unknown ID stays quarantined for operator reconciliation.
  - `transcript`: `{provider_item_id:string,role:'user'|'assistant',text:string,context?:'real'|'roleplay',usage?:object}`. Append-only, session/item idempotent; conflicting replay rejected. Stored columns id uuid, session_id, provider_item_id, role, text, context, provider_usage jsonb, created_at. Returns WorkerSession with `transcript_item_id` added. Default context real.
  - `lead_patch`: `{fields:Record<string,{value:string,evidence_item_ids:string[]}>,contact_confirmation?:{channel:'phone'|'email',value:string,readback_item_id:string,confirmation_item_id:string},followup_consent?:{granted:boolean,channel?:'phone'|'email'|'all',request_item_id?:string,response_item_id:string}}`. Evidence IDs are provider_item_id strings, session-bound persisted transcript. Fields allowed name,company,website,industry,region,language,call_volume,current_tools,main_need,contact_preference,phone,email,summary,next_step,pilot_interest. Each field needs real user evidence; contact confirmation requires saved identical phone/email, real assistant readback and real user confirmation AFTER readback. A consent grant additionally requires confirmed matching contact and real assistant specific request + later real user response. Both question and response must be newer than the latest persisted consent decision; question must follow current contact confirmation, whose readback follows current contact field evidence. Unsolicited withdrawal `{granted:false,response_item_id}` requires only real user evidence and clears permission even without any confirmed contact/question. The followup_decision_at and followup_decision_item_id watermark survives contact changes; stale decisions cannot restore permission, while an exact current decision replay is idempotent. Runtime is responsible for semantic validation; SQL enforces evidence identity/role/context/order and distinct records. Any contact change invalidates its confirmation and all followup consent. Lead columns: session_id PK, fields jsonb (full evidence objects), contact_confirmed boolean, contact_confirmation jsonb, followup_consent boolean, followup_consent_evidence jsonb, followup_decision_at timestamptz, followup_decision_item_id text, created_at,updated_at.
  - `usage`: `{observed_cost_usd:number,final?:boolean,provider_event_id?:string,provider_usage?:object}`. Optional event ID and raw usage receipt append to sales_usage_events with conflicting replay rejected. Monotonic cumulative observed cost. `final=true` means authoritative final provider usage, never approximation; usage_state='settled'. Active reservation remains held until terminal state. Worker must request termination on ceiling; DB sets stop_requested/ending automatically at or above ceiling.
  - `termination`: `{state:'requested'|'confirmed'|'unknown',error?:string}`. Requested moves ending; unknown moves quarantined; confirmed moves ended and clears SDP. Budget only released when usage is settled. Confirmed provider termination frees global slot even if final usage pending (unsettled hold remains). Fencing token retained until lease expires so trailing authoritative usage can settle.
  - `fail`: `{error:string}`. Only safe before any unresolved create intent/provider; ends error with settled zero cost. Otherwise rejects, use quarantine.

WorkerSession keys: `session_id,request_id,status,client_connected_at,offer_sdp,answer_sdp,provider_call_id,model,max_minutes,expires_at,created_at,stop_requested,claim_token,lease_expires_at,create_intent_at,create_attempts,reserved_cost_usd,observed_cost_usd,usage_state,provider_termination_state,error`. No token/network hashes. `status`: pending/starting/ready/ending/ended/error/quarantined. `usage_state`: reserved/observed/settled. Worker must terminate if stop_requested, expired, disabled config or budget ceiling reached. Renew never extends expires_at.

Owner reads `sales_leads` and `sales_transcript_items` only through RLS matching sales_configuration.owner_user_id = auth.uid(). `sales_sessions` grants authenticated SELECT only safe columns session_id,status,max_minutes,expires_at,created_at,updated_at,provider_termination_state,error; same owner RLS. All six sales tables enable and FORCE RLS. Service role receives only required SELECT/INSERT/UPDATE, with no DELETE/TRUNCATE/REFERENCES/TRIGGER grants. No authenticated writes, anonymous selects, or worker RPC execution.

## Trusted ingress
Edge requires SALES_ENABLED=true, SALES_ALLOWED_ORIGINS exact comma-separated origins, SALES_HASH_SECRET >=32 chars, SALES_TRUSTED_PROXY_SECRET >=12 chars, and SALES_TRUSTED_NETWORK_HEADER (default x-sales-network-ip). A controlled server proxy strips incoming x-sales-proxy-secret/network headers, derives and normalizes the actual client IP from its trusted ingress, then injects the shared secret and normalized IP. Without this arrangement every POST action fails network_unavailable before any RPC; do not expose the proxy secret in browser bundles. Existing Supabase SERVICE_KEY/SUPABASE_URL remain server-only. Status/end/connected additionally require the trusted proxy and validated network, and remain usable during disabled admissions. Unknown cancellation writes have a database-enforced quota in addition to the proxy request limit. Configure the hosted proxy to rate-limit all requests, including unknown-session cancellation tombstones; the DB cap is an additional bound, not a proxy bypass.

SDP queue contains transient client connection metadata. offer_sdp is scrubbed to empty string after provider persistence and on safe terminal/quarantine paths; it is never included in visitor/owner reads. Expired pending SDP is scrubbed by claim/admission reconciliation. answer_sdp is cleared on confirmed termination.

Ended sessions with confirmed provider termination and unsettled usage retain their monetary holds but are not reclaimed for repeated hangups. Final usage arriving on the still-valid worker lease may settle; otherwise a privileged operator must reconcile authoritative provider receipts. There is no automatic invoice/usage retrieval in this release.

## Explicit provider-expiry reconciliation (2026-09-05)

`sales_reconcile_provider_expiry(p_session_id uuid,p_provider_call_id text,p_checked_at timestamptz,p_http_status integer,p_error_code text,p_error_type text,p_evidence_reference text) -> public state` is `SECURITY INVOKER`, service-role only. It is an operator reconciliation command, never an anonymous/public Edge action. The privileged operator must first verify the authenticated sideband handshake for the exact persisted provider call; SQL validates the evidence envelope, not the external HTTP exchange.

It accepts only a stopped, quarantined session with a known matching provider ID, `provider_termination_state='unknown'`, and an allowlisted `gpt-realtime-2.1` / `gpt-realtime-2.1-mini` model. The database derives the earliest persisted assistant transcript timestamp, which must follow local creation and provider-create intent. That transcript proves the provider session already existed by that time. At least 60 minutes must have elapsed by both the check and the reconciliation. The check must be no more than 15 minutes old, not in the future, and carry exact HTTP404 / `call_id_not_found` / `invalid_request_error` evidence with an audit reference.

Result: `status='ended'`, `provider_termination_state='expired'`, `error='provider_session_expired'`. This explicitly differs from a confirmed hangup ACK. SDP is scrubbed, worker lease/claim are invalidated, and `provider_expiry_evidence` retains policy version, model, anchor/upper-bound timestamps, receipt and audit reference. Exact replay is idempotent; a different receipt cannot overwrite it. Authenticated clients cannot read this new private evidence column. Existing owner RLS remains unchanged.

No usage, reservation, lead or consent value is changed. `sales_admit` already excludes ended sessions from concurrency and includes unsettled financial holds across UTC days. The worker treats `expired` as terminal and never creates or hangs up another call for that row. A generic404, missing transcript, unknown provider identity, unsupported model or59-minute-old transcript is insufficient.

Provider policy verified on2026-09-05: [Realtime session lifecycle](https://developers.openai.com/api/docs/guides/realtime-conversations) states a maximum session duration of60minutes; the guide's configuration example uses `gpt-realtime-2.1`. [Sideband controls](https://developers.openai.com/api/docs/guides/realtime-server-controls) documents the authenticated existing-call WebSocket route. This reconciliation does not infer zero cost or claim authoritative billing settlement.
