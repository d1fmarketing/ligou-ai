# Website timezone context

The native interview reuses an existing owner decision before considering website context. Free owner text remains exact stored evidence with its original provenance; it is not parsed into an IANA choice. Only evidence whose entire trimmed value is a supported named zone is canonicalized. An existing Pacific/daylight-saving answer therefore remains an owner decision and suppresses a redundant timezone question without rewriting history.

A new interview can persist `agenda.contextTimezone` from a valid timezone explicitly present in the selected website candidate, or from the narrow operating-location case below. The retained dedicated timezone item becomes `context_resolved`, with zero answer revision, zero clarification count and no owner evidence. The source claim IDs and evidence references are part of the agenda digest and receipt. Explicit correction of that retained item removes the active inference; previous receipts stay unchanged. The separate business-hours/Sunday/holiday obligations stay open.

The geographic rule applies only when all structured general service territories are in `country_code: US`, `region_state: CA`, have no radius or service-specific territory, and contain no missing, ambiguous or contradictory geography. If a public address is present it must also identify a clear California US postal region. A declared invalid/conflicting timezone prevents fallback. This is an explicitly labeled application inference, not a geographic lookup: no city whitelist, browser/server timezone, tenant default, external geocoder or universal fallback is used. Unrecognized or compound source questions remain unresolved.

Documentation consulted on 2026-09-08: [IANA Time Zone Database](https://www.iana.org/time-zones), [IANA zone1970.tab](https://data.iana.org/time-zones/tzdb/zone1970.tab), [IANA North America data](https://data.iana.org/time-zones/tzdb/northamerica), and [ECMA-402 DateTimeFormat construction](https://tc39.es/ecma402/#sec-createdatetimeformat). IANA identifies `America/Los_Angeles` as the US Pacific representative zone; its representative coordinates are not a boundary/geocoding API. The narrowly restricted US/California mapping is application policy. `Intl.DateTimeFormat` supplies the installed IANA rules for each date; a missing `timeZone` instead selects the system timezone. A fixed `-08:00`/permanent PST value cannot stand in for this zone. Summer and winter tests verify the same local 08:00 with the differing UTC instants. No assertion is made that the installed runtime tzdata equals the latest IANA release.
