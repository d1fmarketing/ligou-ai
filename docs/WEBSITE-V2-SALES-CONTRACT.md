## HTTP (Edge)
POST to sales-session. Authorization `Bearer <session_token>` always required, where session_token is browser-generated 32 random bytes in base64url (43 chars), kept in sessionStorage and never URL. Header is a visitor capability, NOT Supabase Auth. Start JSON `{action:'start',request_id:<uuid>,visitor_id:<uuid>,sdp:<string>}`. Server hashes session token; validates input, allowed Origin, trusted-network hash and runtime heartbeat before atomic admission. Start returns `{session_id,status,max_minutes,expires_at}`; same request_id+token replays same session, conflict token cannot read or start. Status JSON `{action:'status',session_id}` returns `{session_id,status,max_minutes,expires_at,sdp?:<answer only when ready>,error?:<safe code>,provider_termination_state?:<status>}`. End `{action:'end',session_id}` requests stop durably/idempotently, returns same state shape. No provider IDs, visitor hashes, tenant identity, other leads or secrets in visitor responses. CORS exact origin allowlist, no wildcards. No model or identity supplied by visitor is trusted.

## Database and worker boundary
Persistence worker MUST quickly define exact RPC signatures/table columns in `docs/WEBSITE-V2-SALES-RPCS.md` and message runtime worker. Suggested tables: sales_configuration (single configured operator owner; enabled, runtime heartbeat, budget limits); sales_sessions (UUID session, request/token/visitor/network hashes, SDP queue, created/expires, state pending/starting/ready/ending/ended/error/quarantined, provider id, model, reserved/observed cost, usage state, stop_requested, worker lease/fencing); sales_transcript_items (incremental append-only role/text/provider item ID); sales_leads (one per session, incremental confirmed fields, distinct contact_confirmed and followup_consent, summary/next_step). RLS denies anonymous data access; authenticated read only matching configuration owner. No writes into business rules/powers/booking/calendar/approval tables. RPC grants service_role only except owner lead reads.

Runtime consumes a `SalesStore` interface implemented against agreed RPCs, with dependency injection for tests. Operations: claim pending session (lease/fencing), record provider-create intent, persist provider identity/SDP (before public ready), append transcript item, save evidenced lead fields, update observed usage, request/complete termination, reconcile expired sessions. Every write is session-bound and claim-token fenced. Worker must commit caller transcript before accepting evidence-referenced lead tool. A retry of same tool/provider item cannot duplicate data. Admission/replay/status/end handled by Edge/persistence worker, not runtime HTTP proxy.
